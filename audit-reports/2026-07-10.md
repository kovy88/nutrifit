# Daily audit — 2026-07-10

## Implementovaný task
**Přidat index na `profiles.stripe_customer_id`** (Quick wins, první nedokončený task s nejvyšší prioritou po přeskočení dvou security tasků — viz níže).

### Co se změnilo
- Nová migrace `supabase/migrations/20260710000000_profiles_stripe_customer_id_index.sql`.
- Vytváří **partial** index `idx_profiles_stripe_customer_id on public.profiles (stripe_customer_id) where stripe_customer_id is not null`.

### Upřesnění oproti původnímu popisu v plánu
Plán tvrdil, že index zrychlí lookup v `create-portal.js`. Po přečtení kódu to neplatí: `create-portal.js:35` i `stripe-webhook.js:82` filtrují podle `user_id` (primary key), takže jejich dotazy index nepotřebují. Reálný přínos indexu je pro **reverse lookup** — najít profil podle daného Stripe Customer id — což bude potřeba pro webhook reconciliation a pro plánovanou customer-ownership validaci (top security task). Proto:
- **partial** index (`where stripe_customer_id is not null`) — sloupec je NULL pro každého neplatícího uživatele, partial index je výrazně menší a pokrývá přesně equality lookupy podle non-null customer id;
- **ne unique** — defenzivní read scan, ne constraint (historická data by teoreticky mohla nést duplicitní/sdílené customer id).

### 2. Explicitně posílat `redirect_uri` při OAuth token exchange (Bezpečnostní priority) — **vyřešeno, uzavřeno jako `[x]`**
Ověřeno proti kódu, žádná změna nebyla potřeba:
- `api/oura/exchange.js` a `api/whoop/exchange.js` `redirect_uri` **už posílají** a validují (`isAllowedRedirectUri`).
- `api/strava/exchange.js` ho neposílá — ale **správně**. Strava je nestandardní OAuth2 provider; její token endpoint `redirect_uri` při code-exchange nepřijímá (validuje ho jen v authorize kroku). Ověřeno proti udržovanému OSS klientovi **stravalib** (`src/stravalib/protocol.py`, `exchange_code_for_token`), který posílá jen `client_id`, `client_secret`, `code`, `grant_type` — identicky jako náš kód. Přidání `redirect_uri` u Stravy by nemělo žádný přínos a neslo by riziko rozbití produkčního flow.

Toto je přesně ten typ nálezu, kde vendor prose docs (které tvrdí, že se `redirect_uri` má posílat) neodpovídají realitě — v souladu s poznámkou v paměti "third-party API docs unreliable".
